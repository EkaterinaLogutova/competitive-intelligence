# Проверка и тестирование решения

Все команды выполняются в Windows PowerShell из корня репозитория. На текущем этапе
достаточно Python 3.11 или новее; внешние библиотеки не нужны.

## 1 Проверить окружение

```powershell
cd D:\kaspersky\competitive-intelligence
python --version
$env:PYTHONPATH = "$PWD\src"
```

Ожидается Python 3.11 или новее. `PYTHONPATH` сообщает Python, что пакет находится в
каталоге `src`; установка пакета для локальной проверки не требуется.

## 2 Проверить структуру репозитория

```powershell
python -m competitive_intelligence validate
```

Ожидаемый результат:

```text
Проверка пройдена: 6 источников, паспорт выборки совпадает с реестром, 3 файла ответа на месте.
```

Эта команда проверяет, что в реестре ровно шесть уникальных источников, их идентификаторы
совпадают с `data/curated/source_inventory.csv`, JSON корректен, а три файла ответа
существуют и не пусты. Она не проверяет правильность извлечения новостей — для этого есть
следующие уровни.

## 3 Запустить автоматические тесты

```powershell
python -m unittest discover -s tests -v
```

Все тесты должны завершиться статусом `ok`, а итог — `OK`. Тесты проверяют:

- уникальность и валидность реестра источников;
- допустимые состояния страницы, включая корректное состояние `empty`;
- диапазон уверенности классификации от 0 до 1;
- дедупликацию карточек Дзена;
- отсутствие данных аккаунта в публичном результате;
- перевод «вчера», «2 часа назад» и абсолютной даты в ISO 8601;
- полный путь HTML → CLI → JSONL;
- 29 уникальных карточек в сохраненном снимке.

Вместо двух предыдущих команд можно запустить общий сценарий:

```powershell
.\scripts\check.cmd
```

Он сначала проверяет синтаксис файлов Python, затем структуру и модульные тесты. Для
проверки используется файл `.cmd`, потому что Windows часто запрещает запуск `.ps1`.

## 4 Выполнить интеграционный прогон на сохраненной странице

```powershell
$snapshot = "D:\kaspersky\Рубрика «Новости технологий»_ последние и свежие новости сегодня _ Дзен.html"

python -m competitive_intelligence extract-dzen `
    $snapshot `
    --output data\processed\dzen-news.jsonl
```

Ожидаемый результат:

```text
Извлечено записей: 29. Результат: data\processed\dzen-news.jsonl.
```

Каталог `data/processed` исключен из Git. Исходный HTML содержит данные браузерной
сессии, поэтому его тоже не следует коммитить или пересылать как часть решения.

## 5 Проверить количество и структуру записей

```powershell
$records = Get-Content -Encoding UTF8 data\processed\dzen-news.jsonl
$records.Count
$records[0] | ConvertFrom-Json | Format-List
```

Первая команда должна вернуть `29`. У первой записи нужно проверить как минимум:

- `source_id = dzen_computers_news`;
- `page_type = news_aggregator_rubric`;
- непустые `title`, `publisher`, `canonical_url` и `collected_at`;
- `state = ok`;
- `observed_time_text` сохраняет исходное отображаемое время;
- `published_at` содержит нормализованное время ISO 8601.

## 6 Проверить воспроизводимость

```powershell
python -m competitive_intelligence extract-dzen `
    $snapshot `
    --output data\processed\dzen-news-second-run.jsonl

Get-FileHash data\processed\dzen-news.jsonl -Algorithm SHA256
Get-FileHash data\processed\dzen-news-second-run.jsonl -Algorithm SHA256
```

Хеши должны совпасть. Это означает, что один и тот же снимок дает один и тот же результат
и извлечение не зависит от сети, текущего времени или случайности.

## 7 Проверить приватность результата

```powershell
Select-String `
    -Path data\processed\dzen-news.jsonl `
    -Pattern 'strongestId|externalUid|passportLinks|avatar'
```

Команда не должна вывести ни одной строки. Она проверяет известные маркеры данных
сессии. Это дополнительная защита, а не доказательство полной анонимности любого нового
формата страницы: при изменении структуры входа список проверок нужно расширять.

## 8 Выполнить ручную выборочную сверку

Автотест не понимает, что заголовок или издатель визуально соответствуют странице.
Поэтому нужно открыть сохраненный HTML и сравнить минимум три карточки:

1. первую карточку;
2. карточку с относительным временем, например «2 часа назад»;
3. карточку из нижней части списка.

Для каждой сравниваются заголовок, издатель, аннотация, отображаемое время, исходная
ссылка и URL сюжета Дзена. Если все поля совпадают, интеграционный прогон считается
пройденным.

## 9 Повторить исследовательский анализ

Этот шаг использует отдельное окружение с библиотеками pandas и numpy:

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements-research.txt
.\.venv\Scripts\python.exe scripts\analyze_sources.py
```

Ожидаемый результат — обновленный `reports/source-audit.md`. В нем должны остаться шесть
источников, шесть типов страниц, пять заполненных и одна пустая коллекция, а в разделе
Дзена — 29 карточек десяти изданий.

## Что эти проверки пока не покрывают

- получение новой страницы из сети;
- изменение верстки Дзена после даты снимка;
- переход и извлечение полного текста с сайтов исходных СМИ;
- сетевые лимиты, robots.txt и повторные попытки;
- качество будущих моделей классификации, поиска и генерации сводок.

Эти проверки следует добавлять отдельными слоями. Сетевые тесты не должны заменять
сохраненные проверочные примеры: сайт может быть временно недоступен, а тест результата должен оставаться
воспроизводимым.
