# Инструкция по разметке страниц

Версия схемы: `page-taxonomy-v1`.

Размечается URL вместе с сохраненным снимком страницы. Единица разметки — страница,
а не сайт целиком. Один домен может содержать несколько типов страниц.

## Поля

`platform_type` описывает площадку: СМИ, форум, блог, отзовик, социальная сеть.
`page_type` отвечает на вопрос, что открыто по конкретному URL. `item_type` — какая
повторяющаяся единица извлекается со страницы. `collection_state` заполняется независимо
от типа: `populated`, `empty`, `blocked`, `not_found` или `parse_error`.

Для каждой метки сохраняются версия инструкции, уверенность разметчика от 0 до 1 и
короткий комментарий, если решение неоднозначно.

## Рабочие классы

| `page_type` | Как распознать | `item_type` |
| --- | --- | --- |
| `review_collection` | один объект и список отзывов о нем | `user_review` |
| `review_catalog` | список объектов, переход к отзывам нужен отдельно | `review_object` |
| `publisher_blog_feed` | лента публикаций одного редакционного автора | `editorial_post` |
| `news_aggregator_rubric` | карточки разных СМИ с переходами к оригиналам | `news_card` |
| `forum_section_index` | перечень тем с ответами и последней активностью | `forum_topic` |
| `topic_collection` | подборка социальных публикаций по теме | `social_post` |

Пустая тематическая подборка остается `topic_collection` со значением `empty`. Ее нельзя
перемечать в `parse_error` только из-за отсутствия карточек.

## Спорные случаи

- Издатель и автор — разные поля. Название СМИ не переносится в `author`, если подписи
  конкретного человека нет.
- Дата последнего сообщения в теме не считается датой создания темы.
- Число голосов за сервис не считается числом отзывов.
- Относительное время сохраняется как показано на странице; нормализованная дата
  вычисляется относительно времени снимка и помечается как приблизительная.
- Если страница визуально загрузилась, но блоки не распознаны, это `parse_error`. Если
  сама страница сообщает, что записей нет, это `empty`.
- Новый шаблон не следует насильно относить к ближайшему классу. В пилотной разметке для
  него ставится техническая метка `unknown`, то есть «неизвестный тип», и пишется
  объяснение в комментарии.

## Контроль качества

Первые 50 страниц каждого класса независимо размечают два человека. Расхождения
обсуждаются после завершения пакета, чтобы один разметчик не подстраивался под другого.
После согласования обновляются инструкция и `label_version`, а исходные оценки не
перезаписываются.

Согласованность считается отдельно для типа площадки, страницы, материала и состояния
сбора. Для этого используется коэффициент согласованности Кохана. Дополнительно
составляется таблица расхождений. Если коэффициент по типу страницы ниже 0,8, корпус не
передается в модельный эксперимент: сначала уточняются определения и повторно
размечается спорная часть.

Train/test split делается по доменам. Иначе страницы одного шаблона попадут в обе части,
и оценка будет отражать запоминание верстки, а не работу на новом источнике.
