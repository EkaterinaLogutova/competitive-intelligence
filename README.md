# Исследование источников для медиамониторинга

Репозиторий подготовлен для тестового задания команды исследований технологий
управления интеллектуальной собственностью на основе ИИ и аналитики. Это небольшая
исследовательская работа: сначала определяется единица анализа и собираются наблюдения,
затем формулируются гипотезы и простой исходный вариант, после чего сравниваются модели
и варианты масштабирования.

## Исследовательский вопрос

Можно ли привести страницы разных типов к общей структуре, не потеряв особенности
новостей, отзывов, форумов и социальных публикаций, а затем использовать эти данные для
автоматической разметки и получения производной аналитической информации?

В исходной выборке шесть URL. Они оказались шестью разными типами страниц, поэтому
классификация ведется на трех уровнях:

```text
platform_type → page_type → item_type
```

Состояние получения (`populated`, `empty`, `blocked`, `not_found`, `parse_error`)
хранится отдельно от типа страницы.

## Что сделано

- вручную исследованы шесть источников и зафиксированы доступные поля;
- создан паспорт выборки для анализа в Python;
- из сохраненной страницы Дзена извлечено 29 карточек десяти изданий;
- реализовано повторяемое извлечение данных из сохраненной страницы в таблицу записей;
- добавлена нормализация относительного времени;
- сформулированы гипотезы для классификации страниц, обнаружения новых типов и
  информационных метрик;
- подготовлены три отдельных ответа на задание;
- написаны модульные и сквозные тесты.

## Чего в проекте пока нет

На шести URL нельзя честно обучить и оценить классификатор. Поэтому в репозитории нет
модели, которая показывает 100 процентов на шести известных строках. Следующий
модельный этап начинается после расширения корпуса и разметки страниц с нескольких
доменов на каждый класс.

Также пока не реализованы модули сбора для всех площадок. Текущий кодовый пример
работает с локальным снимком Дзена, чтобы результат можно было повторить независимо от
сети и текущей версии страницы.

## Как запустить

Нужен Python 3.11 или новее. Основной код и тесты используют только стандартную
библиотеку.

```powershell
cd D:\kaspersky\competitive-intelligence
$env:PYTHONPATH = "$PWD\src"
python -m competitive_intelligence list-sources
```

Команда должна вывести шесть адресов из задания. Это проект с командной строкой, а не
сайт, поэтому отдельного окна или веб-интерфейса после запуска не появится.

## Быстрая проверка

```powershell
.\scripts\check.cmd
```

Сценарий проверяет синтаксис, состав репозитория и запускает 12 тестов. Ожидаемый итог —
`OK`. Файл `.cmd` используется специально, чтобы проверка работала даже при запрете
PowerShell-сценариев. Ту же проверку можно выполнить отдельными командами:

```powershell
python -m competitive_intelligence validate
python -m unittest discover -s tests -v
```

Подробная инструкция с проверкой JSONL, воспроизводимости и приватности находится в
[`docs/testing.md`](docs/testing.md).

## Повторить извлечение Дзена

```powershell
$snapshot = "D:\kaspersky\Рубрика «Новости технологий»_ последние и свежие новости сегодня _ Дзен.html"

python -m competitive_intelligence extract-dzen `
    $snapshot `
    --output data\processed\dzen-news.jsonl
```

Для текущего снимка ожидается 29 записей. Исходный HTML содержит данные браузерной
сессии и не должен попадать в Git; `data/processed` также исключен из репозитория.

В Windows PowerShell 5.1 при чтении результата нужно явно указывать UTF-8:

```powershell
Get-Content -Encoding UTF8 data\processed\dzen-news.jsonl -First 1 |
    ConvertFrom-Json |
    Format-List
```

Без `-Encoding UTF8` русские буквы могут отображаться неправильно, хотя сам файл при
этом не поврежден.

## Повторить первичный анализ данных

Анализ использует библиотеки pandas и numpy. Они устанавливаются отдельно, потому что
не нужны для извлечения данных и основных тестов.

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements-research.txt
.\.venv\Scripts\python.exe scripts\analyze_sources.py
```

Программа обновит [`reports/source-audit.md`](reports/source-audit.md): состав выборки,
полноту наблюдаемых полей, способы доступа и распределение изданий в снимке Дзена.

## Логика следующих экспериментов

1. Собрать не менее 300 страниц с несколькими доменами на класс.
2. Провести двойную разметку и уточнить инструкцию по спорным случаям.
3. Взять простые правила за начальную точку сравнения.
4. Сравнить логистическую регрессию, градиентный бустинг и векторные представления текста.
   Для честной оценки использовать train/test split по доменам.
5. Провести leave-one-class-out: по очереди исключать один класс из обучения и проверять,
   распознает ли модель новый тип.
6. После надежной разметки материалов исследовать группы сюжетов, информационные
   метрики и генерацию дайджестов.

Поиск подходящих документов с последующей генерацией ответа относится только к
последнему пункту. Этот подход часто называют RAG. Он может помочь составить сводку со
ссылками, но не заменяет сбор, разметку и проверку качества данных.
